# Прототип системы автоматической классификации и маршрутизации электронных документов

**Этап 1 (текущая версия): инфраструктура + приём документов + извлечение текста.**

Репозиторий создан **как самостоятельная новая система** на основе только подходящих компонентов прежнего проекта `documents_recognition`: адаптированы загрузчики PDF/DOCX/изображений, Tesseract OCR, взаимодействие с MinIO/S3 и основа технологического стека. Семантический поиск, фрагментация для ChromaDB и сама ChromaDB не переносились.

## Что готово

- FastAPI: приём и валидация PDF/DOCX/изображений, ограничение размера 20 МБ, извлечение текста.
- Текстовые PDF обрабатываются без OCR; для страниц с коротким/отсутствующим текстовым слоем вызывается Tesseract при `ENABLE_OCR=true`.
- DOCX: извлечение абзацев и таблиц, изображения: OCR.
- PostgreSQL: документы, секции, подготовленные таблицы истории классификаций, ручных проверок и правил маршрутизации.
- MinIO (S3 API): исходные файлы, presigned-ссылка на оригинал.
- Streamlit: загрузка, список документов, извлечённый текст, демонстрационные правила маршрутизации.
- Docker Compose: четыре сервиса (PostgreSQL, MinIO, FastAPI, Streamlit).
- Автономные тесты извлечения текста и API с моками S3/БД.

**Чего пока нет:** размеченного датасета, обученных ML-моделей, классификации, применения маршрутов, ручного изменения класса и результатов экспериментов. Не подставлять фиктивную вероятность или класс. Таблицы под будущую логику созданы заранее.

## Запуск

Требуется Docker Engine / Docker Desktop с поддержкой Compose v2.

**Примечание о MinIO (октябрь 2026):** официальные Docker-образы MinIO Community Edition перестали быть общедоступны в прежних реестрах. Для учебной среды в Compose указан сторонний публичный mirror `public.ecr.aws/y9w4h2u9/minio:RELEASE.2025-09-07T16-13-09Z`, который заявлен как неизменённая копия исходной версии. Достоверность сторонних сборок не проверялась; для производственного использования следует самостоятельно собирать и аудировать MinIO из исходников или использовать доверенный S3-совместимый сервис. Образ можно заменить через `MINIO_IMAGE` в `.env`. В окружении разработки он не скачивался и не запускался.

```bash
docker compose up --build -d
```

Открыть:

- Streamlit: http://localhost:8512
- FastAPI Swagger: http://localhost:8082/docs
- MinIO Console: http://localhost:9201 (`minioadmin` / `minioadmin` — только для локальной разработки)
- PostgreSQL: `localhost:5434`, БД `classifier_db`, пользователь `docuser`, пароль `docpass` (только для локальной разработки)

Проверить API:

```bash
curl http://localhost:8082/health
curl http://localhost:8082/classes
curl -F "file=@/путь/к/документу.pdf" http://localhost:8082/documents/upload
curl http://localhost:8082/documents
```

Конфигурация запуска задаётся в `docker-compose.yml`. Для удалённого сервера выставить `S3_PUBLIC_ENDPOINT_URL` в окружении Compose или в `.env` (см. `.env.example`), чтобы браузер мог открывать оригиналы. Пример: `S3_PUBLIC_ENDPOINT_URL=http://192.168.1.10:9200`.

Для остановки:

```bash
docker compose down
```

**Важно:** `docker compose down -v` удалит тома PostgreSQL и MinIO, а значит все документы и данные.

## План разработки

1. **Готово в коде этапа 1:** инфраструктура, извлечение PDF/DOCX/сканов, сохранение в PostgreSQL/MinIO, UI первичного приёма и тесты.
2. **Следующий этап:** размеченный датасет шести классов: разделение train/validation/test, проверка дубликатов и шаблонной утечки.
3. Обучение `TfidfVectorizer + LogisticRegression`, сериализация `joblib`, API `/classify`.
4. Обучение `intfloat/multilingual-e5-small` + `LogisticRegression`, с воспроизводимыми настройками эмбеддингов.
5. Сравнение Accuracy, Precision, Recall, Macro/Weighted F1, матриц ошибок, времени обработки.
6. Калибровка/оценка confidence и подбор порога по валидационной выборке (начальная гипотеза 0.70).
7. Маршрутизация, `requires_review`, ручное подтверждение и исправление, история предсказаний в `classification_results`.
8. Финальный UI, функциональные тесты, итоговый Compose, диаграммы и материалы для пояснительной записки.

**Принцип:** OCR confidence и classification confidence — разные показатели. OCR confidence соответствует качеству распознавания (0–100), classification confidence — достоверности выбранного класса (0–1). Для логистической регрессии значения вероятностей не следует автоматически считать хорошо калиброванными: подбор порога требует проверки на валидации.

## Тесты

В Python-окружении со всеми зависимостями, указанными в `requirements-dev.txt`:

```bash
python -m pytest -q
```

Тесты загрузчиков запускаются без Docker. Проверка реальной интеграции с PostgreSQL и MinIO требует поднятых контейнеров (на этом этапе автоматические интеграционные тесты ещё не добавлены).
